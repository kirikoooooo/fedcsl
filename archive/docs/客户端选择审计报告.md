# FedCS 与 Oort 客户端选择实现审计报告

## 一、FedCS 审计

### 1.1 公式正确性

| 项目 | 论文/理论 | 当前实现 | 结论 |
|------|-----------|----------|------|
| 采样概率 q | \( q_i \propto p_i \cdot G_i / \sqrt{t_i} \) | `raw = self.p * self.G / np.sqrt(t_safe)` | ✅ 正确 |
| 聚合权重 | \( w_i = p_i / (K \cdot q_i) \) 归一化 | `w = self.p / (self.K * q_safe)` 后归一化 | ✅ 正确 |
| 无偏性 | 逆概率加权保证无偏 | 权重已含 p_i，归一化后 sum=1 | ✅ 正确 |

### 1.2 实现细节检查

**fedcs_selector.py**

- **p 归一化**（L24）：`self.p = self.p / self.p.sum()` ✅
- **t 默认值**（L25）：`t = np.ones(N)` 当 `t is None` ✅
- **G 默认值**（L26）：`G = np.ones(N)` 当 `G is None` ✅
- **除零保护**（L31-33）：`t_safe = np.maximum(self.t, 1e-8)`，`raw = np.maximum(raw, 1e-10)` ✅
- **get_aggregation_weights**（L56-64）：
  - 仅选中客户端有权重：`np.where(select_mask != 0, ...)` ✅
  - fallback：`s <= 0` 时返回 `(self.p * select_mask)` ✅

**FedCSL_All.py 调用**

- **data_weights**（L368）：`p_i = len(y_fed[i]) / len(y_all)` ✅
- **采样**（L501-504）：`sample_clients_mask_by_probability(q_list, sample_nums, seed)` ✅
- **聚合**（L506-508）：`fedavg_fedcs(w_locals, y_fed, agg_weights_list)` ✅
- **G 更新**（L510-512）：`g_proxy = 1/(1+loss)`，`update_gradient_norm(idx, g_proxy)` ✅

### 1.3 发现的问题与建议

| 问题 | 严重性 | 说明 |
|------|--------|------|
| **round 0 聚合权重错误** | 高 | round 0 全选时，\(q_i \propto p_i\)（G=t=1），故 \(w_i = p_i/(K \cdot q_i) = 1/K\)，退化为均匀权重；全选时应按数据权重 \(p\) 聚合，而非逆概率 |
| **t_i 恒为 1** | 中 | `update_client_time` 从未调用，耗时未接入，q 公式中 \(\sqrt{t_i}\) 恒为 1，无法体现异构耗时 |
| **G 更新对象** | 低 | 对所有客户端更新 G，包括空数据客户端（`client_losses[idx]=0` 时 `g_proxy=1`），可考虑仅对参与训练的客户端更新 |

## 二、Oort 审计

### 2.1 核心逻辑正确性

| 项目 | 预期行为 | 当前实现 | 结论 |
|------|----------|----------|------|
| time_stamp | 仅对被选中的客户端更新 | FedCSL_All 仅对 `select_mask[i]>0` 的客户端调用 `update_client_util` | ✅ 已修复 |
| unexplored | 仅在被选中并上报 feedback 时移除 | `update_client_util` 内 `unexplored.discard`，且只对选中客户端调用 | ✅ 已修复 |
| reward 归一化 | 支持负 reward（如 -loss） | 使用 `count > 0` 替代 `reward > 0` 收集 moving_reward | ✅ 已修复 |

### 2.2 UCB 公式

```python
sc = (creward - min_r) / range_r + sqrt(0.1 * log(cur_time) / max(1, time_stamp))
```

- **含义**：`time_stamp` 越大（最近被选）→ 探索项越小；`time_stamp` 越小（很久未选）→ 探索项越大，鼓励重新选择 stale 客户端 ✅
- **与标准 UCB**：标准 UCB 用 `sqrt(log(T)/n_i)`，此处用 `time_stamp` 近似“staleness”，语义合理 ✅

### 2.3 实现细节检查

**oort_selector.py**

- **register_client**（L83-92）：初始化 `count=0`、`unexplored.add` ✅
- **update_client_util**（L119-126）：更新 reward、duration、time_stamp、count，`unexplored.discard`，`successfulClients.add` ✅
- **_get_norm**（L149-156）：`_min = min(aList) * 0.999` 避免 range=0，支持负数 ✅
- **clip_value**（L204）：`creward = min(reward, clip_value)` 对负 reward 正确 ✅
- **explore 池**（L232-259）：`init_reward` 可为负，`unexploredSc > 1e-12` 时用概率抽样，否则用 `sorted_unex[:exploreLen]` 取前若干 ✅

### 2.4 发现的问题与建议

| 问题 | 严重性 | 说明 |
|------|--------|------|
| **exploreLen 公式**（L241） | 低 | `exploreLen = min(exploreLen, int(sample_window * exploreLen))`，当 sample_window=5 时恒为 min(a,5a)=a，未起到限制作用，可考虑改为按 `numOfSamples` 的固定比例 |
| **round 0 全选** | 设计 | 第 0 轮全选，所有客户端被探索，`unexplored` 在第 0 轮后为空，explore slot 无法生效；若希望 explore 生效，需在 round 0 也使用 Oort 选择 |
| **duration 固定 1.0** | 中 | 未接入真实训练耗时，Pacer 与 duration 惩罚无法体现真实系统效率 |
| **Pacer 依赖 successfulClients** | 设计 | `_calculate_sum_util` 仅统计 `successfulClients` 中的客户端，当前仅对选中客户端更新，逻辑一致 ✅ |

## 三、FedCSL_All 中与选择相关的流程

### 3.1 训练与聚合顺序

1. 所有客户端参与训练（`for idx, c in enumerate(clientList)`）
2. 计算 `client_losses`、`scores`
3. 根据选择方法得到 `select_mask`
4. Oort：仅对 `select_mask[i]>0` 的客户端调用 `update_client_util`
5. FedCS：用 `agg_weights` 做 `fedavg_fedcs`；对所有客户端调用 `update_gradient_norm`
6. 聚合：Oort/Uniform/OMP 用 `fedavg(w_locals, y_fed, combined_scores)`，FedCS 用 `fedavg_fedcs`

### 3.2 潜在问题（非 Oort/FedCS 专属）

- **空数据客户端**：若某客户端 `len(X_fed[idx])==0`，会 `continue`，不执行 `w_locals.append`，`w_locals` 长度可能小于 `numClient`，与 `fedavg` 期望的 `len(w)==len(score_list)` 不一致，需注意边界情况

## 四、总结

| 模块 | 实现正确性 | 主要问题 |
|------|------------|----------|
| **FedCS** | 公式与实现正确 | t_i 恒为 1，未接入真实耗时 |
| **Oort** | 公式与流程正确 | duration 固定，round 0 全选导致 explore 无效 |
| **FedCSL 集成** | 调用正确 | 无 |

**建议**：若需更贴近论文，可考虑：
1. FedCS：round 0 全选时使用 p 作为聚合权重；接入 `update_client_time` 或真实耗时估计
2. Oort：接入真实训练时长；round 0 可选使用 Oort 选择以保留 explore 效果
