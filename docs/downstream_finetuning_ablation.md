# 下游微调（不同标注比例）消融实验设计方案

> 版本：v1（2026-10-24）
> 依据：中期报告《FedCSL-Spilter：面向非 IID 多变量时间序列的自适应尺度拼接联邦 Shapelet 表征学习》、现有代码（FedCSL_All.py / train.py / blocks.py）、已完成的 HAR/FaceDetection/LSST/Epilepsy/SleepEDF 实验与系统效率微基准。
> 状态：设计稿，待导师确认后实施。

---

## 1. 实验目的与要回答的问题

中期报告的评估协议统一为 **"冻结联邦预训练 encoder → 提取表征 → 训练 SVM → 报告最后 10 轮测试集平均准确率"**。该协议衡量的是**表征质量**，但没有回答：

1. **标签效率（label efficiency）**：预训练表征在标注数据只占 1% / 5% / 10% / 20% / 50% 时，下游性能保留多少？这直接呼应课题背景中"标签稀缺"的设定。
2. **可迁移性代价**：Spilter 客户端只训练了 top-m 个尺度，聚合出的全局表征在下游微调时是否与 FedCSL 全尺度训练等价？
3. **冻结 vs 微调**：冻结 encoder 只训分类头，与全参数微调之间有多大差距？差距是否随标注比例变化？

本实验是在**不改变预训练产物的前提下**新增的下游评测维度，与现有 SVM 协议并列，用于补强论文"可迁移"目标并支撑中期报告第（2）（3）条遗留问题的回答。

---

## 2. 设计总原则：只有两个变量

| 维度 | 状态 | 取值 |
|---|---|---|
| 方法（预训练产物） | **变化** | FedCSL、Spilter-m2、Spilter-m4、FedAvg（弱监督对照）、FedBYOL 或 FedU2（SSL 对照，选一个） |
| 下游标注比例 | **变化** | 1%、5%、10%、20%、50%、100% |
| 预训练超参 | 固定 | 与主实验完全一致（见 §3） |
| 微调协议 | 固定 | 冻结 encoder + 线性头（见 §4 主协议 A） |
| 数据划分 / 采样 / 种子 | 固定 | 见 §5 |
| 测试集 | 固定 | 始终为完整原始测试集，**不随比例裁剪** |

任何一组实验报告必须同时标注方法名、α、比例、采样种子四元组，缺失任何一项的结果不得进入汇总表。

## 3. 预训练阶段：参数固定清单（全部沿用主实验）

微调实验**不重新预训练**，直接复用主实验已保存的全局模型 checkpoint。预训练侧参数冻结如下（与 config/configSpilter.yml 及主实验口径一致）：

| 参数 | 固定值 | 出处 |
|---|---|---|
| 尺度锚点 | R=8，均匀分布在 [0.1T, 0.8T] | 中期报告 §2.1 |
| 距离度量 | `dist_measure=mix`（欧氏+余弦+互相关三分块） | configSpilter.yml |
| 温度 | temperature=0.1（命令行默认） | FedCSL_All.py:62 |
| 对比损失系数 | l=0.01、ls=1、β=0.4、γ=0.7 | configSpilter.yml model.params |
| 本地训练 | lr=0.01、wd=1e-4、momentum=0.9、batch=32、numEpoch=1 | configSpilter.yml |
| 联邦设置 | numClient=50、numRound=200、dirichlet_alpha=0.1（主 α，扩展 α=1.0 可选） | configSpilter.yml |
| 随机种子 | seed=42 | 主实验默认 |
| Spilter 尺度配置 | m∈{2,4}（主实验最优档位；m1 已有完整矩阵，可作为低资源对照补跑） | 中期报告 §4.1 |
| 客户端选择 | **关闭**（`use_client_selection: False`） | 主实验默认 |

**Checkpoint 选择固定为最后一轮（round 200）的全局模型**。理由：

- 主实验的"最后 10 轮平均"是**评估口径**，不是模型口径；微调需要单个权重文件，最后一轮是唯一无歧义、可复现的选择。
- 若希望与"最后 10 轮平均"严格对齐，可后续增加"最后 10 轮权重平均"的 checkpoint 保存（FedCSL_All.py 目前不支持，需小改），但 **v1 版本统一用 round 200**，论文中如实说明即可。

## 4. 下游微调阶段：参数固定策略（核心）

### 4.1 主协议 A：冻结 encoder + 线性分类头（全矩阵实验用）

**这是全实验矩阵（方法 × 比例 × 数据集）唯一采用的微调协议**，超参全部复用现有 `_linear_probe_eval` 实现（FedCSL_All.py:1952），零新增自由度：

| 项 | 固定策略 |
|---|---|
| 冻结范围 | `shapelets_blocks` + `projection`（LayerNorm）**全部冻结**；只训练新增的 `nn.Linear(d, C)` 分类头。projection 只有 LayerNorm 的可训练参数（极少），但为保持"表征完全不变"的口径，一并冻结 |
| 表征提取 | 用 `transform()`（train.py:1069，即 `forward(optimize=None)` 输出）**一次性提取全部训练/测试表征**，冻结场景下只需提取一次，微调不同比例/种子时直接复用 |
| 分类头 | 单层线性，与现有 `linear_probe` 一致；权重随机初始化（seed=42） |
| 优化器 | Adam，lr=1e-3，wd=1e-4 |
| batch size | 256（小比例时 `min(batch, n_train)` 自动降档，与现有实现一致） |
| 训练轮数 | max_epoch=200，ReduceLROnPlateau（factor=0.5，patience=max(10, epoch/10)，min_lr=1e-4） |
| 早停口径 | 与现有 `_linear_probe_eval` 一致：无验证集时在**训练子集**上取 best，再用该 best 权重报测试集精度（注意：小比例下训练集上取 best 会高估，见 §5 的验证集方案） |
| 分类头种子 | torch.manual_seed(42) + cuda.manual_seed_all(42)，与现有实现一致 |

**为什么主协议选"冻结+线性头"而不是全微调：**

1. 与 SVM 协议**直接可比**——同一表征、同一冻结口径，仅分类器形式不同，可以画出"SVM vs 线性头 vs 全微调"三层对照；
2. 唯一变量是标注比例，任何解冻都会引入"微调程度"这一第三变量，污染方法间对比；
3. 1% 比例下样本极少，全解冻必然过拟合，冻结协议才能体现"表征本身"的标签效率。

### 4.2 子消融 B：解冻策略（仅 HAR、α=0.1、FedCSL + Spilter-m4 两个方法）

在主协议之外，用**单点消融**回答"应该微调多少"：

| 变体 | 解冻范围 | 分类头 | 目的 |
|---|---|---|---|
| B1 | 全冻结（= 主协议 A） | 线性头 | 基线，与 SVM 协议对照 |
| B2 | **全部解冻**（encoder + 头） | 模型自带 `linear` 头（blocks.py:563）。注意：预训练全程 `optimize=None`，该头从未被训练过，**必须随机初始化** | 回答"全微调上限" |
| B3 | 全冻结 + **非线性头**（256 隐层单层 MLP，ReLU） | MLP 头 | 排除"线性头是瓶颈"的干扰 |
| B4（可选） | 只解冻 shapelet 参数（`shapelets_blocks`），冻结 projection + 头 | 线性头 | 定位增益来源 |

B2/B3/B4 的微调超参需**先定标后固定**：在 10% 比例上做一次 lr ∈ {1e-2, 3e-3, 1e-3, 3e-4, 1e-4} × 优化器 ∈ {Adam, SGD(momentum=0.9)} 的小网格，选定一组后**全矩阵固定**，不逐点调参。B2 全解冻建议额外用 `ReduceLROnPlateau` + 早停（验证集上），并固定 max_epoch ≤ 100 防止小比例下过拟合。

### 4.3 Spilter 的下游微调口径（必须写进论文）

- Spilter 客户端只上传所选尺度的参数，但服务器**按尺度粒度聚合**，未被上传的尺度保持服务器原值，因此**全局模型始终是完整的 8 尺度模型**。
- 下游微调统一使用**全局全尺度模型**，**不重新执行 top-m 裁剪**。尺度选择是联邦训练期的系统属性（决定通信量/显存/计算），下游评测协议对 FedCSL 与 Spilter 必须完全一致，否则无法公平比较"表征质量"。
- 可另设一个**补充分析变体**（不进入主矩阵）：用 `encode_mix_forward_selected_scales` 只取客户端周期评分 top-m 尺度的子表征做冻结微调，用于分析"被裁剪尺度的信息在下游是否可丢弃"。该变体属于方法分析，不参与方法排名。

### 4.4 α 的选择（固定原则）

- 主矩阵固定 **α=0.1**：与系统效率微基准（HAR、α=0.1、batch=32、RTX 3090）同口径，便于"精度—显存—标签效率"三点联动叙事。
- 扩展实验（可选，单独成表）：α=1.0（弱异质），验证结论对异质度的稳健性。
- 不强求 6 个 α 全跑：微调实验的边际信息主要在比例维度，α 全矩阵留作 rebuttal 弹药。

## 5. 标注子集采样协议（固定规则）

| 规则 | 固定值 |
|---|---|
| 采样方式 | **分层采样**（stratified，按类别比例），保证每类至少 1 个样本（1% 比例下强制下限：每类 min 1，多的类补足配额） |
| 子集构造 | 只从**完整训练集**中抽取标注子集；测试集永远完整不动 |
| 采样种子 | 每个比例固定 3 个采样种子 {0, 1, 2}（代码内 `np.random.default_rng(seed)`），报告 **mean ± std** |
| 验证集 | 从标注子集内再按 8:2 分层划出验证集用于早停（仅当标注子集 ≥ 50 样本时；否则退化为训练集取 best，并在结果表脚注标注"无验证集"）。**注意：此规则比现有 `_linear_probe_eval` 多一个验证集划分，实施时作为 fixed rule 全矩阵统一，不与逐点调参混淆** |
| 类别编码 | 复用现有 `class_to_idx` 逻辑（按 y_train 出现顺序） |

**样本量参考**（以服务器实际数据为准）：HAR 训练集 ≈ 7352（6 类），1% ≈ 74 样本、每类 ≈ 12；FaceDetection 训练集 ≈ 5890（2 类）；Epilepsy-TSTCC 训练集 = 7360（2 类，T=178，本机实测 2026-10-24，`torch.load('./Epilepsy/train.pt')` 确认）。实施前用 `torch.load` 打印实际 shape 并写进 `data/fine_tuning_*.md` 头部。

> ⚠️ 数据集名注意：`-dataset` 必须写 `Epilepsy-TSTCC`（FedCSL_All.py 中的分支名），写 `Epilepsy` 会落入 UEA 分支并因缺 `Multivariate_ts/` 报错。

## 7. 评估指标与结果记录

### 7.1 指标

1. **主指标**：完整测试集准确率，mean ± std（3 采样种子）。
2. **保留率**：`Acc(ratio) / Acc(100%)`，用于画标签效率曲线（x=比例，y=准确率，每方法一条线）。
3. **相对 SVM 锚点**：`Acc_ft(100%) − Acc_svm(最后10轮平均)`，回答"冻结微调 vs SVM 协议"的协议间差异（预期两者都应接近，差距 > 2pp 需排查实现 bug）。

### 7.2 结果文件

- 汇总表：新建 `data/fine_tuning_HAR.md`、`data/fine_tuning_Epilepsy.md`，格式对齐 `data/HAR_results.md`（方法 × 比例矩阵 + 加粗最优 + 脚注种子数）。
- 原始日志：沿用 `./result/{dataset}/` 的 txt 日志。**一次训练跑完该方法的全部比例 × 种子**（预训练只做一次，微调消融在训练结束后基于最后一轮全局模型统一执行），`--description` 固定格式 `ft_{dataset}_{method}`（如 `ft_epi_spilter_m4`），保证与现有结果目录兼容、可 grep。
- 日志中每个比例一行：`ratio | per-seed test acc | mean ± std`，头部记录 checkpoint 口径（final-round）与验证集规则。
- 论文表格：新增 `tab:fine_tuning_har`（方法 × 比例）、`tab:unfreeze_ablation`（B 组）、正文新增"下游微调与标签效率"小节，与"最后 10 轮 SVM 平均准确率"口径并列说明。

### 7.3 收敛曲线（可选加分项）

B 组全解冻实验记录每 epoch 验证精度，画"1% vs 100% 下的过拟合曲线"，支撑 §4.1 中"小比例必须冻结"的论断。

## 8. 代码实现落地方案

**已实现（2026-10-24，FedCSL_All.py）**，本机合成数据冒烟测试通过：

1. **命令行参数**：`--ft-ratios "0.05,0.1,0.2,0.5,1.0"`（启用消融，逗号分隔比例列表）、`--ft-seeds 3`（每比例采样种子数）、`--ft-val-split 0.2`（验证集划分比例，固定规则）、`--ft-min-samples 50`（启用验证集的最小标注子集规模）。
2. **训练循环内**：`train()` 中解析 ft 参数并在训练开始前打印启用信息。
3. **训练结束后**：基于**最后一轮全局模型**（内存中）一次性执行 `_finetune_subset_eval()`——`server.transform()` 提取冻结表征 → RobustScaler（与轮内 SVM 评估同口径）→ 各比例 × 种子分层抽样 → `_train_linear_head()`（与 `_linear_probe_eval` 共用同一训练循环，超参来自 `evaluation.linear_probe` 配置块）。
4. **checkpoint 保存**：消融启用时额外保存 `./checkpoint/{dataset}/{date}_{dataset}_model_final_round.pt`（协议 A 的固定 checkpoint 口径；`save_model` 保存的 best 模型仍照旧，供 B 组对照）。
5. **结果输出**：控制台 + 结果 txt 日志，每比例一行 `ratio | per-seed test acc | mean ± std`；消融异常不阻断主实验（try/except 记录到日志）。
6. **待实现（B 组）**：`_finetune_e2e_eval()`（全解冻/分层解冻，走 `model.forward(optimize='acc')`），触发参数可复用 `--ft-ratios` + 新增 `--ft-unfreeze {none,all,shapelets}`。

## 9. 风险与注意事项

1. **小比例样本方差大**：1% HAR 每类仅 ~12 样本，单种子结果不可信——3 种子是硬性要求，报告中必须带 std，不得只报均值。
2. **Epilepsy 样本量极小**（训练集约 137）：1% 无意义，比例起点改为 5%；其结论定性为主。
3. **早停口径漂移**：现有 `_linear_probe_eval` 在训练集上取 best，小比例下会系统性高估。§5 的验证集规则是新引入的口径变化，**全矩阵统一使用**并在论文中说明，不与旧 linear_probe 结果混排。
4. **checkpoint 缺失风险**：主实验若未保存 round 200 权重（checkpoint_every=0），需先小改代码补存，或从 result txt 确认保存逻辑后再跑微调。实施第一步就是核对 `result/{dataset}/` 与模型保存路径。
5. **GPU 排期**：主矩阵 90×2 组微调全部是"提一次表征 + 训小线性头"，单组分钟级，总开销远低于预训练补跑，可排在主实验间隙执行。
6. **口径一致性**：论文正文必须写清三套评估口径（SVM / 冻结线性头 / 全微调）各自的适用问题，避免审稿人质疑"为什么不用同一协议排名"。

## 10. 与中期报告及后续计划的衔接

- 本实验直接服务课题目标中"标签稀缺……在下游分类任务上验证有效性"的表述，补足中期报告 §4 中缺失的**标签效率维度**。
- 若 B 组显示"全微调在 50%/100% 下显著优于冻结+SVM"，则论文结论可升级为"Spilter 表征不仅 SVM 可分离，且微调上限更高"，形成三层证据链：SVM（表征可分）→ 冻结线性头（标签效率）→ 全微调（上限）。
- 该实验完成后，中期报告"实验覆盖仍不完整"清单（问题 1）可划掉一项，并为答辩 PPT 提供"标签效率曲线"一张核心图。
