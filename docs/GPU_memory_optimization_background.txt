GPU 显存优化背景与研究动机

================================================================================
一、深度学习训练中的 GPU 显存瓶颈
================================================================================

深度学习模型的训练通常以 mini-batch 为单元迭代进行。每次迭代包含两个阶段：
前向传播（forward pass）和反向传播（backward pass）。在前向传播中，训练样本
被依次送入各计算层，每个层的输出（称为激活，activation）被保存在 GPU 显存中，
供后续反向传播计算梯度时复用。在反向传播中，一旦对应层的梯度计算完成，该层的
激活便被释放。

这种机制下，GPU 显存消耗主要由三部分构成：
  (1) 模型参数：网络中各层的可学习权重；
  (2) 优化器状态：如 SGD 的动量缓冲区、Adam 的一阶/二阶矩估计；
  (3) 中间激活：前向传播中各层输出，用于反向传播时计算梯度。

其中，中间激活是显存消耗的主要来源。对于一个具有 D 个变量（通道）、序列长度
为 T、batch size 为 B 的 MTS 样本，单个 shapelet 子模块 f_{r,m} 的激活存储需求为：
    O( BD(T-L_r+1)L_r + BD_repr(T-L_r+1) )
其中 L_r 为 shapelet 长度，D_repr 为表征维度。当 B、D、T 较大时，R×M 个子模块
的激活同时驻留在 GPU 显存中，极易导致显存溢出（Out-Of-Memory, OOM）。

与模型参数和优化器状态不同，中间激活的大小随着 batch size、输入维度和序列长度
线性增长，而 GPU 显存总量是固定的（如常见的 16 GB、24 GB、32 GB）。对于许多
资源受限的实际应用场景（如 IoT 边缘设备、移动端推理），显存限制尤为突出。

================================================================================
二、激活检查点（Activation Checkpointing, AC）技术
================================================================================

为解决显存瓶颈，一种有效的方案是激活检查点（AC），也称为梯度检查点
（gradient checkpointing）。其核心思想是：在前向传播中有选择地丢弃部分中间
激活，在反向传播需要这些激活时再从最近保存的检查点重新计算（recomputation）。

AC 本质上是一种"以计算换显存"的策略——通过增加额外的计算（重算）来减少显存
占用。因此，AC 虽然可以降低显存峰值，但会引入额外的重算开销，导致训练时间增加。

AC 已被主流深度学习框架原生支持，如 PyTorch 的 torch.utils.checkpoint 和
TensorFlow 的 tf.GradientTape。然而，这些默认实现通常对整个模型层进行无差别
检查点，缺乏针对模型特性的优化。

================================================================================
三、检查点规划问题（Checkpointing Planning Problem）
================================================================================

AC 的核心挑战在于制定高质量的检查点计划（checkpointing plan），即决定哪些层的
激活应丢弃、哪些应保留，以在给定显存预算下最小化训练时间开销。这一问题被称为
"检查点规划问题"。

检查点规划的困难在于：不同计算层之间存在复杂的依赖关系。丢弃某层的激活后，
反向传播时重算该层可能需要递归地重算依赖的前驱层，产生额外的计算和显存开销。
例如，若同时丢弃层 l2 和 l3 的激活，重算 l3 必须先重算 l2，形成递归链。

================================================================================
四、现有通用规划器及其局限
================================================================================

现有检查点规划器主要分为两类：

（1）启发式方法（Heuristic-based）
代表工作：Mimose [Kusumoto et al., 2019]、Monet [Kumar et al., 2019]、
DTR [Kirisame et al., 2020]。
策略：贪心选择显存/计算比值最高的层进行检查点，或基于层的显存使用和重算成本
进行启发式决策。
优点：实现简单，兼容任意计算依赖的模型。
局限：贪心策略缺乏全局信息，容易陷入局部最优，计划质量不稳定。

（2）优化方法（Optimization-based）
代表工作：Checkmate [Jain et al., 2020]、ROC [Schuler et al., 2023]。
策略：将检查点规划建模为优化问题，以最小化训练开销为目标、显存约束为条件。
局限：通用模型中各层之间存在复杂的数据依赖，导致约束包含多项式或二次非线性
项，无法精确求解，只能进行近似线性化处理。近似误差导致解的质量受限。

此外，一般规划器需要枚举所有计算层（数十到数百个），搜索空间巨大，求解时间长。

================================================================================
五、MAST：面向 Shapelet 模型的定制化 AC 规划器
================================================================================

针对上述通用规划器的局限，Liang 等人提出了 MAST（Memory-Aware Shapelet
Training），第一个面向 CSL 的 Shapelet Transformer（ST）编码器定制化的检查点
规划器。MAST 的设计基于两个关键观察：

O1：显存由子模块主导。ST 编码器的激活显存集中在 R×M 个 shapelet 子模块 f_{r,m}
上，后续 loss 计算等操作的显存开销相对极小（Θ(BD_repr)，D_repr 为常数）。

O2：子模块之间相互独立。不同尺度 r 和距离度量 m 的子模块之间无数据依赖——
它们分别对输入做距离计算后仅做拼接输出，因此任意子模块的激活可以独立丢弃和
重算，不会产生递归依赖。

基于这两个观察，MAST 将规划空间从"所有计算层（数十到数百个）"压缩到"R×M 个
独立子模块（典型值为 24）"，从而将检查点规划问题建模为二元线性规划（Binary
Linear Program），可使用 Gurobi 等标准求解器精确求解，不再受非线性约束困扰。

MAST 的工作流程：
  Phase 1（Profiling）：首轮训练时 checkpoint 所有子模块，逐个子模块测量前向
    计算成本 c_{r,m} 和 workspace 显存 w_{r,m}；
  Phase 2（求解）：根据给定显存预算 B，求解 BLP，获得最优计划 y*；
  Phase 3（应用）：后续训练中按计划丢弃/重算子模块的激活。

实验结果表明，在相同显存预算下，MAST 相比 Mimose、Checkmate 和 Monet 减少
1.43%-7.65% 的训练时间开销；在相同的计算开销下，节省 6.4%-21.9% 的 GPU 显存。
在 16 GB 预算的 MotorImagery 数据集上，MAST 相比第二快的 Checkmate，全局峰值
显存降低 4.7%，反向传播耗时更短，表明其计划能更好地利用有限显存来减少高成本
层的重算。

================================================================================
六、显存优化在联邦学习中的意义
================================================================================

在联邦学习（Federated Learning）场景下，显存优化问题更为突出：

（1）异构设备：联邦学习的客户端通常为异构设备（边缘设备、移动终端、嵌入式
系统），其 GPU 显存差异巨大（从几百 MB 到几 GB 不等）。一个对所有客户端统一的
模型架构可能导致低显存设备无法参与训练。

（2）多客户端并行：多个客户端在同一 GPU 上串行或交替训练时，显存碎片化和
峰值叠加问题更加严重。

（3）通信与计算耦合：联邦学习中客户端的本地训练占据主要时间开销。在显存
受限条件下，合理的训练策略（如选择部分尺度参与训练）可以在不显著降低模型
质量的前提下，大幅减少显存占用和训练时间。

这些动机驱动了 Spilter 架构中的 Knapsack-Lagrangian 显存约束尺度分配方案——
在模型架构层面为每个客户端选择适合的尺度子集，使得客户端在本地资源限制下
最大化训练效率，同时保证全局尺度覆盖。
